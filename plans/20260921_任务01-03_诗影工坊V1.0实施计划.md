## 2. 后端设计要点

### 2.1 批量文本解析(batch_parser)

- 首个非空行必须为 `POEM_VIDEO_BATCH_V1`,否则报错。
- 头部元数据:`title / dynasty / author`(缺失给 warning,创建批次时可由表单补齐)。
- `[GLOBAL]` 可缺省;width/height/fps/num_frames 非正整数报错;`negative_prompt` 支持多行。
- `[SCENE:cover]` 可选,`[SCENE:1..N]` 不限数量;scene key 重复报错;编号断裂给 warning;缺 prompt / speech 指明 scene 报错。
- 多行值规则:`key:` 后换行,持续收集到下一个「当前上下文已知 key 行」或节标题为止;prompt/speech 原文保留不改写。
- 输出:`{metadata, global, scenes[], warnings[], errors[]}`;有 errors 时前端禁止创建。
- 场景排序:cover → 1 → 2 → …(数字升序)。

### 2.2 上传(uploads)

- `POST /api/uploads`:multipart 多文件,png/jpg/jpeg/webp,单文件大小上限走配置(默认 20MB),存 `uploads/{upload_group_id}/uuid_原文件名`,返回 upload_id、缩略图 URL、按文件名猜测的 scene_key(cover.png→cover,01.png/1.png→1)。
- `GET /api/uploads/{id}/image`:受控读取(resolve 防目录穿越)。
- 创建批次时把绑定图片**复制**到 `uploads/{batch_id}/`,VideoTask.image_path 落库。

### 2.3 批次(batches)

- `POST /api/batches/parse`:纯文本解析,返回结构化结果。
- `POST /api/batches`:body 含 raw_batch_text + image_bindings{scene_key→upload_id} + 表单元数据;后端**重新解析校验**(服务端单一事实来源),每个场景必须已绑定图片,否则 422。
- `GET /api/batches`、`GET /api/batches/{id}`、`GET /api/batches/{id}/tasks`。

### 2.4 任务02模块

- workflow_adapter:读模板→深拷贝→按 workflow-map.yaml 注入 image/prompt/negative/speech/尺寸帧数/唯一 filename_prefix(`{batch_id}/{scene_order:02d}_{scene_key}`);启动时校验映射节点存在,失效则健康检查失败。
- comfyui_client:httpx 封装 POST /prompt、GET /queue、GET /history/{id}、GET /view;WebSocket /ws(断线重连 + HTTP 回查兜底);超时与错误分类。
- 提交策略:按 scene_order 逐个提交,保存 prompt_id;中途失败不丢已提交记录,Batch 置 partial_failed。
- 状态同步:后台 asyncio 任务订阅 ComfyUI WS + 周期性 history 对账,更新 VideoTask/Batch;`WS /api/ws/batches/{id}` 向浏览器推送状态变化;服务重启后按 prompt_id 查 history 恢复,无法确认置 recover_pending。
- 输出识别:按 prompt_id 从 history 的 Save 节点输出定位 mp4,经 /view 下载复制到 `outputs/{batch_id}/`,落库 output_path/filename/subfolder/type。
- retry:单独重试生成新 prompt_id,保留旧错误信息(错误字段拼接历史),复用原图片/参数。

### 2.5 任务03模块

- `GET /api/tasks/{id}/video`(inline 预览)、`GET /api/tasks/{id}/download`(attachment,文件名=诗名_序号_场景简名.mp4);仅允许访问数据库登记路径,resolve 防穿越,不存在返回 404。
- `GET /api/system/health`、`/api/system/status`:API/SQLite/ComfyUI HTTP/Queue/模板映射/数据目录可写;不触发推理。
- 启动恢复:startup 时对 queued/running 任务做 history 对账。

## 3. 前端设计要点

- 路由:`/`(新建批量任务)、`/batches`(列表)、`/batches/:id`(详情)。
- 新建页:基本信息表单 + el-upload 拖拽多图(排序/标记 cover/重绑定)+ 批量文本框 + 「解析任务」/「清空」+ 场景预览卡片(scene key、缩略图、speech、prompt 摘要、宽高/fps/帧数)+「创建批次」;顶栏显示 共N场景/已绑定M张/可否提交。
- 详情页:批次信息、总进度、ComfyUI 连接状态、任务表(状态/prompt_id/起止时间/错误/预览/下载/重试)、「全部加入生成队列」按钮;WS 实时刷新(断线降级轮询)。
- Element Plus,简洁生产工具风格。

## 4. 验证计划

1. `pytest`(backend/tests):parser 11+ 用例、workflow_adapter、comfyui_client(MockTransport)、API 冒烟(上传→解析→建批次→查任务)。
2. `pnpm -F frontend run typecheck`、`pnpm -F frontend run build`。
3. Playwright E2E(本地起 uvicorn + vite preview):生成 5 张测试图 → 上传 → 粘贴《宿建德江》批量文本 → 解析 → 绑定 → 创建批次 → 刷新持久性断言;截图存 `Walkthroughes/screenshots/20260921_任务01_工程骨架与批量输入解析/`。
4. docker-compose 配置语法级检查(`docker compose config` 如本机有 docker;无则说明)。

## 5. 明确不做

- 不实现 H3 推理逻辑、不改写 prompt/speech/negative_prompt。
- 不做 FFmpeg 合片、TTS、多用户(V1.1+/V2.0)。
- 不伪造真实 ComfyUI 验收结论。
