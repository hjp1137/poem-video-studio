## 2. Agent 安全设计(任务04 §2 / §10)

- 只有固定动作:`nvidia-smi` 查询/`-pl`、`systemctl <verb> <注册 unit>`、`journalctl -u <注册 unit> -n 1..1000 --no-pager`;全部参数数组 + shell=False + timeout + stderr 捕获。
- 不提供 /shell /exec /command;service name 只来自注册表,GPU index 只来自实查列表,watts 只来自驱动 min/max 区间。
- 可选 sudo 前缀(`AGENT_USE_SUDO=1` 时 `sudo -n`),sudoers 示例只放行 nvidia-smi 与已注册 unit 的固定动词,不含 NOPASSWD: ALL。
- gpu-power.json 读写:临时文件 + os.replace 原子替换;非法 JSON 报配置错误,不影响 Agent 存活。
- 监听 127.0.0.1(可配),可选 AGENT_TOKEN Bearer 校验。

## 3. 关键流程

- 设 Power Limit:实查该卡 min/max → 区间校验 → `nvidia-smi -i N -pl W` → 回读 → 返回 before/requested/after。
- 全部设置:`PUT /api/server/gpus/power-limit` 后端逐卡调 Agent,逐卡返回结果,单卡失败不伪装成功。
- 开机自动应用:页面写配置 → Agent 落 `/etc/poem-video-agent/gpu-power.json` → `poem-video-gpu-power.service`(oneshot,After=nvidia-persistenced)开机执行 `apply_power`,单卡失败记录 index 不阻断。
- 服务控制:注册表 name→unit 解析;`systemctl show` 读 ActiveState/SubState/MainPID/ExecMainStartTimestamp 映射 process_state;HTTP health(注册表 url)得 health_state;两层分离,active≠Ready。
- 一键准备(后端编排,后台任务 + 状态轮询,前端显示步骤进度):01 Agent→02 GPU→03 功耗→04 进程巡检(只读,标注非受管)→05 停冲突服务(已停 skip)→06 启 H3(running+healthy skip;running+unhealthy restart)→07 等 H3 Ready→08 启 ComfyUI→09 等 Ready→10 Queue API 检查→11 READY;失败即停、返回 failure_step、不隐式回滚。
- 停止保护:有 PoemVideo 任务在跑或 ComfyUI 队列非空时,stop/restart 默认 409,`force=true` 二次确认后执行并落审计。

## 8. 返工二(2026-09-22 用户指示):冲突服务改为自动检测

不再依赖 Profile 写死的 stop_services,由 Agent 自动检测「当前占用 GPU 显存」的服务:

- Agent 新增 `GET /v1/gpu-workloads`(nvidia-smi 计算进程 → /proc/<pid>/cgroup 归属 docker 容器/systemd unit/裸进程 → docker ps 只读映射容器名,按显存降序)与 `POST /v1/gpu-workloads/{container}/stop`;
- 安全约束:docker stop 只对「当前检测到占用 GPU 的容器」放行(动态白名单),停止任意容器名直接拒绝;systemd/裸进程负载只读展示(前者控制仍走注册表);docker ps 失败时降级显示容器短 ID 不整体失败;
- Studio API 代理 `/api/server/gpu-workloads*` 并审计 action=workload.docker_stop;
- 总览页「② 停止冲突服务」改为自动检测清单(容器/服务/进程 + GPU 分布 + 占用显存 + 可停/只读标识),与 Profile.stop_services 中仍在运行的注册服务合并去重;无占用显示 ✓。
