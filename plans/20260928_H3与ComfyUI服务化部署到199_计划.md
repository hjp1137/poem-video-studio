# 2026-09-28 H3 与 ComfyUI 服务化部署到 199 计划

## 目标

任务05遗留的服务化真实验收:在 199 上把 MiniMax H3(vLLM)与 ComfyUI 部署为 systemd 服务,登记注册表,页面「手动逐项准备」可真实启动并转 READY。

## 服务器资产(已核实)

- 模型:`/data/AI_Models/MiniMax-H3`(303G,含 FL2VA/Turbo LoRA),9-11 曾以 vLLM 跑通(h3_headers.txt:x-model FL2VA,峰值 15.5G/卡)
- vLLM 源码环境:`/data/AI_Models/vllm-omni/.venv`(vllm 0.28.0,Python 3.12)
- ComfyUI 源码环境:`/data/AI_Models/ComfyUI-H3/.venv`(含 custom_nodes/ComfyUI-vLLM-Omni,url 为工作流参数,默认 localhost:8000)
- GPU 4×4090 当前全空闲;/ 697G、/data 2.6T 可用

## 部署方案

### 端口

- vLLM:8101(宿主 8000 已被 poem-video-api 容器占用,历史命令的 8000 不可用;custom node 默认 url 是工作流参数,真实工作流里写 http://127.0.0.1:8101/v1)
- ComfyUI:8188(容器经 172.17.0.1 访问,与 .env COMFYUI_BASE_URL=host.docker.internal:8188 一致)

### systemd unit(按任务05 §4/§5 要求)

1. `/etc/systemd/system/minimax-h3.service`:ExecStart 复用 bash history 中已验证的 vllm serve 命令(FL2VA+Turbo LoRA,4 卡 TP=2/text-tp=4/offload),仅两处调整:--host 127.0.0.1(收敛暴露面,仅本机 custom node 访问)、--port 8101;User=root(服务器现状);Restart=on-failure;TimeoutStopSec=300;WorkingDirectory=/data/AI_Models/vllm-omni
2. `/etc/systemd/system/comfyui.service`:ExecStart=.venv/bin/python main.py --listen 0.0.0.0 --port 8188;WorkingDirectory=/data/AI_Models/ComfyUI-H3;Restart=on-failure;TimeoutStopSec=60
3. 均不设 enable(开机自启会抢占 4 卡,与既有业务容器冲突;由页面手动启动,符合「手动逐项准备」设计)

### 注册表

`/etc/poem-video-agent/services.yaml`:minimax_h3 health 改为 `http://127.0.0.1:8101/health`(vLLM 标准 health 端点,加载中 503→agent 两层状态如实区分 active/ready);comfyui 保持 8188/system_stats。

## 验证

1. systemctl start comfyui → curl 127.0.0.1:8188/system_stats
2. systemctl start minimax-h3 → 轮询 curl 127.0.0.1:8101/health(模型加载预计数分钟)
3. agent /v1/services 两服务 active+ready;后端 /api/server/services 同
4. 容器内验证可达 host.docker.internal:8188/8101 不需要(8101 仅本机)
5. 页面手动逐项 ③④ 启动 → READY;SSH 隧道 Playwright 截图
