# 2026-09-21 任务03：V1.0 成片下载、运行状态、Docker 部署与端到端验收

## 1. 任务目标

在任务01、任务02完成后，将 PoemVideo Studio V1.0 收敛为可长期使用的本地生产工具。

本任务重点：

- 输出视频预览与下载
- 任务运行状态可视化
- Docker Compose 部署
- 数据持久化
- 服务健康检查
- 失败恢复
- README 与运维文档
- 完整端到端验收

V1.0 不要求自动把所有片段合并成一条完整视频；自动合片作为 V1.1 后续功能。

## 2. 输出管理

建立：

```text
/data/poem-video-studio/
├── uploads/
├── outputs/
├── database/
└── logs/
```

每个 Batch 独立目录：

```text
outputs/{batch_id}/
├── 00_cover.mp4
├── 01_scene_1.mp4
├── 02_scene_2.mp4
├── 03_scene_3.mp4
└── 04_scene_4.mp4
```

如果 ComfyUI 输出不在该目录，可采用：

- 安全复制
- bind mount
- 受控软链接

三种方式之一，最终必须让 PoemVideo Studio 有稳定的输出路径。

禁止通过模糊 glob 规则错误关联别的任务文件。

## 3. 下载 API

实现：

```text
GET /api/tasks/{id}/video
GET /api/tasks/{id}/download
```

要求：

- 只能访问数据库登记的输出文件。
- 防止目录穿越。
- 文件不存在时返回明确 404。
- 下载文件名使用诗名 + 场景顺序 + 诗句简名。
- 支持浏览器直接预览 MP4。

## 6. Docker

建立生产可用：

```text
docker-compose.yml
```

服务：

```text
poem-video-api
poem-video-web
```

要求：

- FastAPI 与前端独立容器。
- SQLite / uploads / outputs / logs 均持久化到 /data。
- Workflow 模板挂载可控。
- 支持服务器重启后自动启动。
- 不把 MiniMax H3、vLLM、ComfyUI 打进本项目镜像。
- 不修改现有 ComfyUI 容器或 Python 环境。

Linux 连接宿主机 ComfyUI 可使用：

```yaml
extra_hosts:
  - "host.docker.internal:host-gateway"
```

实际地址通过 .env 配置，不硬编码。

## 8. 服务启动与恢复

服务器或 Docker 重启后：

1. PoemVideo Studio 自动启动。
2. SQLite 数据保留。
3. 已完成任务仍可预览/下载。
4. queued / running 任务启动后通过 prompt_id 查询 ComfyUI history。
5. 已完成则补记 completed。
6. 已失败则补记 failed。
7. 无法确认时标记 recover_pending，不得直接丢弃。

## 11. 最终端到端验收

在真实服务器上使用《宿建德江》完整执行：

### 输入

- 封面图 1 张
- 诗句场景图 4 张
- 一次粘贴整首诗批量 Prompt

### 操作

用户只需要：

1. 打开 PoemVideo Studio。
2. 上传 5 张图。
3. 粘贴一次批量文本。
4. 点击“解析任务”。
5. 核对场景。
6. 点击一次“全部加入生成队列”。

从第 6 步之后，不再进入 ComfyUI 手工复制任何 Prompt。

### 输出

必须得到：

```text
00_cover.mp4
01_scene_1.mp4
02_scene_2.mp4
03_scene_3.mp4
04_scene_4.mp4
```

并能在页面：

- 逐段预览
- 逐段下载
- 查看生成状态
- 对失败段单独重试

## 12. 质量验收

PoemVideo Studio 本身不得引入以下问题：

- 改写 speech
- 修改 prompt
- 修改 negative_prompt
- 场景错绑图片
- 场景顺序错乱
- 把上一首诗的输出绑定到当前任务
- 重试覆盖已完成视频且不可追溯
- API 重启后任务全部丢失

视频画质、文字稳定性和声音表现由 H3 Workflow / Prompt 决定，但系统必须保证传参完整、准确、可追踪。
