# 2026-09-21 任务02：MiniMax H3 / ComfyUI Workflow 适配、批量入队与实时状态

## 1. 任务目标

在任务01基础上完成 PoemVideo Studio 与当前 MiniMax H3 / ComfyUI 的真实集成，实现：

> 一个 Batch 中的全部场景 → 一次点击 → 自动构造 N 份 Workflow → 依次提交 ComfyUI Queue → 实时追踪状态 → 找到每个场景的最终 MP4。

不得改写现有 MiniMax H3 / vLLM 的推理实现。

## 4. Workflow Adapter

实现：

```text
backend/app/services/workflow_adapter.py
```

职责：

1. 读取 Workflow 模板。
2. 深拷贝。
3. 注入场景首帧。
4. 注入 prompt。
5. 注入 negative_prompt。
6. 注入 speech。
7. 注入 width / height / fps / num_frames。
8. 生成唯一 filename_prefix。
9. 返回可直接 POST /prompt 的完整 JSON。
10. 不修改原模板文件。

输出命名建议：

```text
{batch_id}/{scene_order:02d}_{scene_key}
```

例如：

```text
a1b2c3/00_cover
a1b2c3/01_scene_1
a1b2c3/02_scene_2
```

## 6. 批量提交策略

点击“全部加入生成队列”后：

1. 读取 Batch 所有 pending / failed 且待提交的场景。
2. 按 scene_order 排序。
3. 每个场景独立生成 Workflow。
4. 逐个 POST /prompt。
5. 保存每个返回的 prompt_id。
6. 更新任务为 queued。
7. 若中间一个任务提交失败，不得丢失前面已成功提交的 prompt_id。
8. Batch 状态应反映 partial 状态。

“一次点击”不等于同时并行推理。实际执行顺序由 ComfyUI Queue 决定。

## 7. 状态模型

VideoTask 扩展字段：

- comfy_prompt_id
- status
- output_path
- output_filename
- error_message
- started_at
- finished_at

状态：

```text
pending
submitting
queued
running
completed
failed
cancelled
```

Batch 状态：

```text
draft
parsed
queued
running
completed
partial_failed
failed
```

## 8. 状态同步

优先使用 ComfyUI WebSocket 获取实时执行事件。

同时使用 /history/{prompt_id} 做最终结果确认，避免仅依赖 WebSocket。

必须解决：

- 浏览器刷新后仍可恢复任务状态。
- API 服务重启后可通过数据库中的 prompt_id + ComfyUI history 恢复。
- WebSocket 断线后自动重连。
- 重连期间通过 HTTP 回查兜底。

## 9. 输出文件识别

不能仅凭“最后生成的文件”猜测输出。

必须根据：

- prompt_id
- ComfyUI history 输出

定位本任务对应 MP4。

保存：

- output filename
- output subfolder
- output type
- 可访问或可复制的实际文件路径

## 10. API

新增：

```text

GET  /api/system/comfyui
```

### retry

单场景重试必须：

- 不影响已完成场景。
- 生成新的 ComfyUI prompt_id。
- 保留历史错误信息。
- 不复用旧 prompt_id。
- 默认复用同一图片、prompt、speech 和参数。

## 12. 声音与画面参数传递要求

系统只传递用户已经生成好的内容，不擅自把“口播式读白”改回“古诗朗诵”。

必须原样保留 speech 与 prompt 中的以下策略：

- 普通话口播式读白
- 不唱歌
- 不吟唱
- 不吟诵
- 不拖腔
- 不旋律化

多音字替代文本只作用于 speech，不得修改图片内容。

## 13. 故障处理

必须覆盖：

- ComfyUI 未启动
- Workflow 模板不存在
- 节点映射错误
- 图片文件无法被 ComfyUI 访问
- POST /prompt 拒绝
- Queue 中断
- WebSocket 中断
- history 中任务失败
- history 完成但未返回 MP4
- API 服务中途重启

错误信息必须落库，前端显示可诊断信息。

## 15. 验收标准

使用《宿建德江》：

- 1 个 cover + 4 个 scene。
- 页面点击一次“全部加入生成队列”。
- 后端自动提交 5 个 ComfyUI prompt。
- ComfyUI Queue 能看到 5 个任务。
- 页面可看到 queued → running → completed。
- 每个场景的首帧、Prompt、speech 均与 Batch 中数据一致。
- 无需人工进入 ComfyUI 再次复制粘贴。
- 5 个任务均能定位自己的 MP4。
- 任一任务失败后可单独重试。
- API 或浏览器刷新不会丢失任务状态。
