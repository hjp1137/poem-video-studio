# 2026-09-22 任务05：模型服务管理与 MiniMax H3 视频环境一键准备

## 1. 任务目标

在任务04 Server Agent 基础上，实现 PoemVideo Studio V1.1 的模型服务控制中心：

- 已登记服务状态查看。
- MiniMax H3 启动 / 停止 / 重启。
- ComfyUI 启动 / 停止 / 重启。
- 预留 Ollama 等已登记模型服务管理。
- 健康检查。
- 服务日志查看。
- 一键“准备 MiniMax H3 视频环境”。
- 与诗词视频批量生成页面联动。

目标：正常日常使用时不再需要 SSH、tmux 或手工输入 H3 / ComfyUI 启动命令。

## 2. 前置核查

在改造成 systemd 前，必须记录当前服务器真实运行方式：

### MiniMax H3

确认：

- 当前启动命令全文
- Python / venv / conda 环境
- vLLM 启动参数
- 模型路径
- CUDA_VISIBLE_DEVICES
- 端口
- 环境变量
- WorkingDirectory
- 当前 tmux 用法
- 正常停止方式
- Ready 判定方式

### ComfyUI

确认：

- 当前启动命令全文
- Python 环境
- ComfyUI 根目录
- custom_nodes
- 监听 IP
- 8188 或真实端口
- 启动参数
- 正常停止方式

禁止根据历史记忆直接重写命令。

先从当前成功环境提取，再服务化。

## 3. 服务注册表

新增 Agent 配置：

```text
/etc/poem-video-agent/services.yaml
```

示例：

```yaml
services:
  minimax_h3:
    display_name: MiniMax H3
    manager: systemd
    unit: minimax-h3.service
    health:
      type: http
      url: http://127.0.0.1:<PORT>/health
      timeout: 3

  comfyui:
    display_name: ComfyUI
    manager: systemd
    unit: comfyui.service
    health:
      type: http
      url: http://127.0.0.1:8188/
      timeout: 3

  ollama:
    display_name: Ollama
    manager: systemd
    unit: ollama.service
    health:
      type: http
      url: http://127.0.0.1:11434/api/tags
      timeout: 3
```

实际内容以服务器为准。

V1.1 不允许 Web 页面动态新增 arbitrary systemd unit。

## 4. MiniMax H3 systemd

建立：

```text
/etc/systemd/system/minimax-h3.service
```

要求：

- ExecStart 复用已经验证成功的命令。
- 使用绝对路径。
- 明确 WorkingDirectory。
- 明确 Environment / EnvironmentFile。
- 明确 User。
- 标准输出进入 journald。
- SIGTERM 可正常停止。
- 设置 TimeoutStartSec / TimeoutStopSec。
- Restart 策略根据实测设置。
- 不使用 tmux 作为 systemd 内层启动方式。

迁移前后必须对比：

- GPU 使用
- 端口
- 模型加载
- H3 生成结果

保证服务化不改变模型行为。

## 5. ComfyUI systemd

建立：

```text
/etc/systemd/system/comfyui.service
```

要求：

- 复用当前成功命令。
- 保持现有 custom_nodes 与模型路径。
- 保持网络访问方式。
- 日志可由 journald 查看。
- 服务异常退出状态清晰。
- 停止后进程不能残留继续占 GPU / 端口。

## 6. Agent 服务 API

新增：

```text
GET  /v1/services
GET  /v1/services/{name}
POST /v1/services/{name}/start
POST /v1/services/{name}/stop
POST /v1/services/{name}/restart
GET  /v1/services/{name}/logs
```

service name 必须来自注册表。

API 请求不接受：

- systemd unit 字符串
- shell command
- PID
- docker command

由 Agent 根据注册表解析。

## 7. 服务状态

返回：

```json
{
  "name": "minimax_h3",
  "display_name": "MiniMax H3",
  "process_state": "running",
  "health_state": "healthy",
  "pid": 12345,
  "started_at": "...",
  "uptime_seconds": 1234
}
```

process_state：

```text
running
stopped
failed
activating
deactivating
unknown
```

health_state：

```text
healthy
unhealthy
starting
unknown
```

systemd active 不等于 Ready。

## 8. 健康检查

### MiniMax H3

优先使用模型服务自身 HTTP health / models endpoint。

如果无独立 health endpoint，选择一个：

- 不触发推理的模型列表接口
- TCP port + API readiness
- 专门增加轻量 health wrapper

不得通过“进程存在”直接判定 Healthy。

### ComfyUI

检查：

- HTTP 8188 可访问。
- 必要时获取 queue / system stats API。
- 不触发视频生成。

## 9. 服务日志

前端允许查看最近 N 行日志。

限制：

- 默认 100 行。
- 最大 1000 行。
- 不允许用户自定义 journalctl 参数。
- Agent 内部固定执行允许的 unit。
- 对日志中可能包含的敏感路径/Token按需遮蔽。

## 12. 一键视频环境 Profile

配置：

```yaml
profiles:
  h3_video:
    display_name: MiniMax H3 视频生成
    gpu_power:
      enabled: true
      watts: 280

    stop_services:
      - ollama

    start_services:
      - minimax_h3
      - comfyui

    readiness:
      minimax_h3_timeout_seconds: 300
      comfyui_timeout_seconds: 120
```

以上 stop_services 必须依据服务器真实 GPU 分配确认后配置，不能为了“释放显存”默认停掉所有服务。

## 13. 一键准备流程

PoemVideo Studio API：

```text
POST /api/server/environment/h3/prepare
GET  /api/server/environment/h3/status
```

执行步骤：

```text
STEP 01 Agent Health
STEP 02 NVIDIA / GPU Health
STEP 03 Apply Power Limit
STEP 04 Inspect GPU Processes
STEP 05 Stop Registered Conflicting Services
STEP 06 Start MiniMax H3
STEP 07 Wait H3 Ready
STEP 08 Start ComfyUI
STEP 09 Wait ComfyUI Ready
STEP 10 Check ComfyUI Queue API
STEP 11 READY
```

前端必须显示步骤进度，而不是长时间只有 loading。

## 14. 幂等与失败恢复

重复执行 Prepare：

- 服务已停止 → skip。
- Power Limit 已正确 → verified。
- H3 已 Running + Healthy → skip start。
- H3 Running + Unhealthy → 按配置 restart。
- ComfyUI Healthy → skip start。

若某步失败：

- 停止继续执行依赖步骤。
- 保留已完成步骤状态。
- 返回 failure_step。
- 返回 error_message。
- 不做隐式大范围 rollback。

## 16. 与批量视频页面联动

新建 / 提交 Poem Video Batch 时显示环境条：

```text
视频环境：READY
```

或：

```text
视频环境：NOT READY
[准备环境]
```

规则：

- 创建/编辑 Prompt 不依赖 H3 Ready。
- 点击“全部加入生成队列”前必须检查 ComfyUI。
- 如果环境未 Ready，提示用户准备环境。
- 不因用户打开批量页面就自动停止模型。
- 修改服务器状态必须是明确用户操作。

## 17. 已登记冲突模型

“关闭正在运行的一些模型”只针对 Registry / Profile 中明确配置的服务。

例如：

```text
ollama
other_video_service
```

未登记 GPU 进程：

- 页面展示。
- 标注“非受管进程”。
- V1.1 不提供 kill 按钮。

## 18. 停止服务安全检查

停止 MiniMax H3 / ComfyUI 前：

- 页面提示是否有当前 PoemVideo Batch 正在生成。
- 如果 ComfyUI Queue 有 running/pending：
  - 默认阻止直接停止。
  - 提供明确的“仍然停止”二次确认（如产品确定需要）。
- 操作日志记录是否强制停止。

## 19. 自动启动策略

系统服务层可配置：

- poem-video-agent：建议 enabled。
- PoemVideo Studio：建议 enabled。
- MiniMax H3：默认是否开机自动启动由用户配置。
- ComfyUI：默认是否开机自动启动由用户配置。

如果服务器平时还有 Ollama 等其他用途，建议 H3 不强制开机即占用资源，而通过“准备视频环境”启动。

## 21. 测试

至少覆盖：

- 服务注册表解析。
- 非注册服务拒绝。
- start / stop / restart 成功。
- systemctl 返回失败。
- service active 但 health fail。
- health timeout。
- 日志行数限制。
- Prepare 全成功。
- Prepare H3 timeout。
- Prepare ComfyUI timeout。
- 已 Ready 重复 Prepare。
- Power Limit 已正确。
- 冲突服务停止失败。
- ComfyUI Queue 非空时停止保护。
- Agent 不可达。

## 22. 真实服务器验收

必须在当前 GPU 服务器完成：

1. 把当前 MiniMax H3 成功命令迁移到 systemd。
2. `systemctl start minimax-h3` 后模型正常加载。
3. 原有 MiniMax H3 视频生成能力正常。
4. `systemctl stop minimax-h3` 后进程正常退出。
5. ComfyUI 同样完成 start / stop / restart。
6. PoemVideo Studio 页面可以控制二者。
7. 页面状态与 systemctl / HTTP 实际状态一致。
8. 服务日志可以查看。
9. “准备视频生成环境”能完整执行。
10. 最终显示 READY。
11. READY 后从 PoemVideo Studio 提交至少一段 H3 视频并成功输出。
12. 整个过程不需要 SSH 或 tmux 手工输入命令。
