# 2026-09-28 启动报错修复:服务注册表部署(199 服务器)

## 问题现象

总览页「视频环境准备 · 手动逐项」点击启动服务时报错:

- 服务 minimax_h3 未在注册表登记,拒绝操作
- 服务 comfyui 未在注册表登记,拒绝操作

「服务速览」面板显示「注册表为空」。

## 根因

非代码 bug,属部署缺步:

1. 199 服务器 `/etc/poem-video-agent/services.yaml` 内容为 `services: {}`(2026-09-22 发布时空注册表占位上线);
2. Agent `registry.resolve()`(`agent/app/services/registry.py:97-103`)查不到条目即 404 拒绝;
3. 总览页启动按钮由 `server/profiles.yaml` 的 `start_services` 驱动,与注册表无关,照常显示,点击后触发上述拒绝。

## 修复内容

在 199 上重写 `/etc/poem-video-agent/services.yaml`,按服务器实际情况登记(agent 无缓存,每次请求重读,无需重启):

- `minimax_h3`:unit `minimax-h3.service`,health `type: none` 并留 TODO——H3 尚未服务化,且 **8001 端口已被 milvus-attu 容器占用**,真实端口须部署时核实避开;
- `comfyui`:unit `comfyui.service`,health `http://127.0.0.1:8188/system_stats`(8188 在 199 空闲);
- **不登记 `ollama`**:199 上 Ollama 是 docker 容器 `ollama-server`(端口 11434),非 systemd unit,登记 systemd 条目无意义;总览页「停冲突服务」已走 Agent 自动检测(/v1/gpu-workloads),不依赖该条目。

仓库内模板 `agent/config/services.yaml.example` 保持不动(通用模板,注释已要求以现场为准)。
