## 一、实现内容

### 1. Workflow Adapter(`backend/app/services/workflow_adapter.py`)

- 读取 API Workflow 模板 → 深拷贝 → 按 `workflows/workflow-map.yaml` 注入:image/prompt/negative_prompt/speech/width/height/fps/num_frames/seed(可选)/filename_prefix;
- 节点 ID 集中于映射配置,业务代码零硬编码;映射加载即校验,节点或 input 不存在时给出具体字段错误;
- 输出命名 `{batch_id}/{scene_order:02d}_{scene_key}`;不修改模板文件。

### 2. ComfyUI Client(`backend/app/services/comfyui_client.py`)

- 封装 `POST /prompt`、`GET /queue`、`GET /history/{id}`、`POST /upload/image`、`GET /view`;
- 连接/请求超时、状态码异常、JSON 异常分类(`ComfyUIUnreachable`/`ComfyUIResponseError`);
- WebSocket 消息解析;地址全部走 `.env` 配置。

### 3. 批量提交与重试(`backend/app/services/task_tracker.py`)

- `submit_batch`:按 scene_order 逐个上传首帧 → 构造 Workflow → POST /prompt → 保存 prompt_id → 状态 queued;中途失败不丢已提交 prompt_id,Batch 反映 partial_failed;
- `retry_task`:单场景重试,复用原图与参数,生成新 prompt_id,历史错误按时间戳保留在前;
- 提交前校验模板/映射,不可用时任务失败并落库可诊断原因。

### 4. 状态同步与恢复

- 后台 `monitor_loop`:优先 ComfyUI `/ws` 事件(execution_start→running 等),断线自动重连,周期 HTTP history 对账兜底;
- `reconcile_task`:按 prompt_id 查 history——完成则从 Save 节点输出定位 MP4(经 `/view` 下载到 `outputs/{batch_id}/`)、落库 output 字段;失败记录 ComfyUI 错误消息;无法确认标记 `recover_pending` 不丢弃;
- 服务启动 `startup_reconcile` 对 queued/running 任务恢复对账;浏览器侧 `WS /api/ws/batches/{id}` 推送状态变化(前端断线自动降级 3 秒 HTTP 轮询)。

### 5. 前端批次详情页增强

「全部加入生成队列」按钮(带二次确认)、ComfyUI 连接状态标签、每任务实时状态/prompt_id/起止时间/错误原因、视频预览与下载、单段重试(带确认)。
