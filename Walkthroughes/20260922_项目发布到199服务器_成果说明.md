## 二、关键实现决策与踩坑

1. **Agent 绑定地址**:Agent 初版监听 127.0.0.1 → 容器经 host-gateway(docker0 = 172.17.0.1)访问被拒;改绑 compose 网络网关(172.27.0.1)仍不通,因为 `host.docker.internal` 实际解析为 docker0 网关 172.17.0.1。最终 **AGENT_HOST=172.17.0.1**:仅容器网络与宿主可达,物理网卡(192.168.3.x)不可达,符合设计文档"仅内部网络"要求。宿主运维访问地址为 `curl http://172.17.0.1:8300/v1/health`。
2. **root 运行适配**:服务器现状所有服务均以 root 运行(含 Ollama/mineru),Agent unit 采用 User=root + AGENT_USE_SUDO=0(root 直接执行 nvidia-smi,无需 sudoers),与 README 的 poemagent 方案等价且权限面更小(无 sudo 依赖)。
3. **空服务注册表**:侦查确认 199 服务器**当前没有运行 MiniMax H3 与 ComfyUI**(GPU 上的 vLLM 进程经核查为 MinerU 文档解析服务 `mineru-api`,cwd=/vllm-workspace;ComfyUI 仅有 Docker 镜像 yanwk/comfyui-boot:cu124-cn 与 /data/comfyui-images,未运行)。因此 services.yaml 登记为空,页面如实显示「注册表为空」而非假状态;H3/ComfyUI 的 systemd 服务化属任务05 真实验收,须先按迁移手册核查清单采集真实启动命令。
4. **端口**:8001 已被 milvus-attu 容器占用——将来 H3 服务化选端口时必须避开,agent/config/services.yaml.example 中 8001 占位需替换。
5. Ubuntu 24.04 需 `apt install python3.12-venv` 后才能建 venv;pip 走清华镜像。
