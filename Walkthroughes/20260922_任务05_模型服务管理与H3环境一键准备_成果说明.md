## 一、实现内容

### 1. Agent 服务控制(任务05 §3、§6~9)

- **服务注册表**(`agent/app/services/registry.py`):`/etc/poem-video-agent/services.yaml` 解析;服务名/unit 名/manager/health 结构校验(unit 名白名单字符,防注册表注入 systemctl 参数);非法配置不崩 Agent,健康接口报 degraded;Web 不能动态新增 unit。
- **systemd 封装**(`systemd.py`):`systemctl show`(LoadState/ActiveState/SubState/MainPID/ExecMainStartTimestampMsec)映射 process_state(running/stopped/failed/activating/deactivating/unknown);动词固定 start/stop/restart;`journalctl -u <unit> -n N --no-pager -o short-iso`,行数内部收敛 1~1000。
- **健康两层判定**:process 与 health 分离;HTTP health(httpx,注册表 url/timeout)——running + HTTP 200 → healthy,active 但 HTTP 未就绪 → unhealthy/starting,绝不以进程存在判定 Healthy。
- **Agent API**:`GET /v1/services`、`/v1/services/{name}`、`POST .../start|stop|restart`、`GET .../logs?lines=N`;name 必须来自注册表(404),请求不接受 unit 字符串/shell/PID/docker 命令。

### 2. Studio API(§10、§13、§18、§20)

- `/api/server/services*` 代理 + 全部修改动作写 ServerOperation;
- **停止保护**(§18):有 PoemVideo 任务排队/执行或 ComfyUI 队列非空时,stop/restart 默认 409(reason+force_required),`force=true` 二次确认后放行,blocked 与 forced 均落审计;
- **一键准备**(`services/env_prepare.py`,`POST /api/server/environment/h3/prepare` + `GET .../status`):后台任务 + 状态轮询;11 步(Agent → GPU → 功耗 → 进程巡检 → 停冲突服务 → 启 H3 → 等 Ready → 启 ComfyUI → 等 Ready → Queue 检查 → READY);
  - **幂等**(§14):已停服务 skip、功耗已一致不重设、Running+Healthy skip、Running+Unhealthy restart、ComfyUI Healthy 只做检查;
  - **失败即停**:返回 failure_step 与 error_message,保留已完成步骤,不隐式 rollback;未预期异常也落状态与审计,不卡 running;
  - 并发守卫:已有任务运行中再次启动返回 409;
  - 审计记录 profile、每步状态、总耗时、failure_step。

### 3. Profile 配置(§12)

`server/profiles.yaml`(h3_video:功耗 280W、停 ollama、启 minimax_h3+comfyui、readiness 300/120s);compose 挂载到容器 `/app/server`;加载即校验(start_services 必须含 h3 与 comfyui)。

### 4. 前端(§11、§15、§16、§17)

- **模型服务页**(`/server/services`):卡片(状态两层 Tag、PID、Uptime、unit、GPU Profile)、启动/停止/重启(停止/重启确认)、日志抽屉(100/300/500/1000 行)、ComfyUI「打开」入口;
- **服务器总览页**(`/server`):READY/NOT READY 大标签 + GPU/功耗/H3/ComfyUI 四项 + 「重新检查」;
- **批量页联动**(§16):新建/列表/详情三页顶部 EnvBanner 只读显示「视频环境:READY/NOT READY」+ 准备入口跳转;「全部加入生成队列」前检查 ComfyUI 健康,未就绪提示但不阻断编辑;打开页面不自动改变服务器状态;未登记 GPU 进程在 GPU 页标注「非受管进程」,V1.1 无 kill 按钮(§17)。

### 4.2 返工二(2026-09-22 用户指示):冲突服务改为自动检测

- Agent 新增 `workloads.py`:nvidia-smi 计算进程 → `/proc/<pid>/cgroup` 归属(docker 容器 / systemd unit / 裸进程)→ `docker ps` 只读映射容器名;`GET /v1/gpu-workloads` 返回占用清单(含 GPU 分布、占用显存、完整命令行、可停标识);
- `POST /v1/gpu-workloads/{container}/stop`:**动态白名单**——仅允许停止「当前实际占用 GPU 显存」的容器,任意容器名拒绝;systemd/裸进程负载只读展示(docker ps 失败降级为容器短 ID);
- Studio API `GET/POST /api/server/gpu-workloads*` 代理 + `workload.docker_stop` 审计;
- 总览页「② 停止冲突服务」改为自动检测清单,与 Profile.stop_services 中仍在运行的注册服务合并去重;新增/未登记的服务只要占用 GPU 即被检测到。
