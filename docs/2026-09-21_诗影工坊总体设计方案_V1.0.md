# 诗影工坊（PoemVideo Studio）总体设计方案 V1.0

> 项目仓库：`hjp1137/poem-video-studio`  
> 中文名称：诗影工坊  
> 英文名称：PoemVideo Studio  
> 文档版本：V1.0  
> 日期：2026-09-21

## 1. 项目背景

当前诗词视频生产流程已经能够通过 MiniMax H3 / ComfyUI 生成 3:4 竖屏诗词视频，但一首绝句通常需要对封面和每句诗分别执行一次生成操作。实际使用中需要重复执行“复制 Prompt → 粘贴 → 选择首帧 → 提交生成”，操作繁琐，且容易出现参数不一致、漏改语音文本、输出文件名混乱等问题。

PoemVideo Studio 的目标是在现有稳定的 MiniMax H3 / ComfyUI 工作流外增加一个轻量控制层，不改动已经跑通的模型服务和核心 Workflow，使用户可以一次上传整首诗词的场景图、一次粘贴整批提示词，然后一键将多个视频任务提交至 ComfyUI 队列，自动生成多个独立 MP4。

## 2. V1.0 核心目标

V1.0 必须完成以下闭环：

1. 支持一首诗词的封面图 + N 张诗句场景图批量上传。
2. 支持一次粘贴整首诗词的批量任务文本。
3. 自动解析封面、诗句、语音文本、正向 Prompt、Negative Prompt 和公共参数。
4. 基于一份已验证可用的 ComfyUI MiniMax H3 API Workflow 模板，为每个场景生成独立任务。
5. 一键将整批任务依次提交到 ComfyUI Queue。
6. 实时展示每个任务的状态：待提交、排队中、生成中、完成、失败。
7. 每个场景独立输出 MP4，并支持单独下载。
8. 单个任务失败时可以单独重试，不影响已经完成的其他任务。
9. 保持现有 MiniMax H3 / vLLM / ComfyUI 运行方式不变。

V1.0 的重点是“批量提交与稳定生成”，不以复杂剪辑、素材资产管理、多人权限系统为目标。

## 3. 设计原则

### 3.1 不改核心模型链路

现有链路继续保持：

```text
ComfyUI
  ↓
ComfyUI-vLLM-Omni / MiniMax H3 Workflow
  ↓
vLLM / MiniMax H3
  ↓
MP4
```

PoemVideo Studio 仅作为控制层：

```text
浏览器
  ↓
PoemVideo Studio
  ↓
ComfyUI API / WebSocket
  ↓
现有 H3 Workflow
```

### 3.2 Workflow 模板化

不在 PoemVideo Studio 中重新实现 MiniMax H3 推理逻辑。

系统保存一份由当前可正常生成视频的 ComfyUI Workflow 导出的 API JSON，例如：

```text
workflows/minimax_h3_poem_v1.json
```

每次生成时仅复制模板并替换动态字段：

- 首帧图片
- 正向 Prompt
- Negative Prompt
- 语音/口播文本
- width / height
- fps
- num_frames
- seed（如需要）
- 输出文件名前缀

### 3.3 ComfyUI Queue 负责 GPU 排队

V1.0 不再引入 Celery、RabbitMQ 等额外任务系统。

PoemVideo Studio 负责“批量组织 + 提交”，ComfyUI 自身 Queue 负责实际生成队列和 GPU 调度。

这样可以最大程度降低对当前 4×RTX 4090 MiniMax H3 环境的影响。

### 3.4 清晰度与稳定性优先

根据现有生成经验，默认策略固定为：

> 文字不动、构图不乱、主体要动、环境微动、镜头少动；宁可动态小一些，也不能以牺牲清晰度、人物稳定性和文字稳定性为代价。

系统不自动改写用户提供的 Prompt，只负责可靠传递和批量执行。

## 6. 用户操作流程

### 6.1 新建诗词任务

用户填写：

- 诗词名称
- 朝代
- 作者

### 6.2 上传图片

支持：

- 封面图（可选）
- 诗句场景图 N 张

推荐文件顺序：

```text
cover.png
01.png
02.png
03.png
04.png
...
```

前端允许一次拖入多张图片，并支持手工调整场景顺序。

### 6.3 粘贴批量任务

统一采用机器可解析格式：

```text
POEM_VIDEO_BATCH_V1

title: 宿建德江
dynasty: 唐
author: 孟浩然

[GLOBAL]
width: 768
height: 1024
fps: 24
num_frames: 121

negative_prompt:
统一反向提示词……

[SCENE:cover]
speech: 宿建德江，唐，孟浩然。
prompt:
封面画面提示词……

[SCENE:1]
speech: 移舟，泊烟渚。
prompt:
第一句画面提示词……

[SCENE:2]
speech: 日暮，客愁新。
prompt:
第二句画面提示词……
```

### 6.4 解析预览

点击“解析任务”后，必须显示场景卡片：

```text
✓ 封面    宿建德江，唐，孟浩然。
✓ 场景01  移舟，泊烟渚。
✓ 场景02  日暮，客愁新。
✓ 场景03  野旷，天低树。
✓ 场景04  江清，月近人。
```

每个场景必须明确绑定一张首帧图片。

解析失败、图片数量不匹配或必填参数缺失时，禁止直接提交。

### 6.5 一键提交

用户点击：

```text
全部加入生成队列
```

后端按场景顺序逐个构造 Workflow 并提交至 ComfyUI。

注意：V1.0 的“一键生成”指一次操作批量加入 ComfyUI Queue，不要求四个视频同时并行推理。

## 7. 视频生成默认规范

V1.0 默认值：

```text
width: 768
height: 1024
fps: 24
duration: 5s
num_frames: 121
```

如实际 H3 Workflow 对 5 秒视频使用 120 帧，则以 Workflow 实测值为准，并把默认值做成配置项。

### 7.1 视觉原则

现有带字首帧的文字视为固定版式元素：

- 不改字
- 不漏字
- 不增加文字
- 不重新书写
- 不改变字体、笔画、位置、大小、排版
- 不让文字漂移、闪烁、抖动或逐渐模糊

画面动态优先来自：

- 主体自然运动
- 水波
- 云雾
- 草木
- 衣摆
- 飞鸟
- 灯火
- 小幅、克制运镜

### 7.2 声音原则

已经验证：五言、七言诗使用“古诗朗诵感”等描述时，MiniMax H3 容易生成唱腔。

因此默认声音描述必须采用：

> 标准普通话，中青年男性，普通话口播式读白，像纪录片旁白或语文老师自然读课文一样说出文字。正常说话语调，不唱歌，不吟唱，不吟诵，不拖腔，不旋律化，不使用戏曲腔，不使用歌曲式表达。

所有场景要求使用同一声线、同一语速和同一音量。

多音字允许只在“实际语音输入文本”中使用读音明确的同音字辅助控制，但不得修改首帧画面中的文字。

## 8. 核心后端模块

建议结构：

```text
backend/
├── app/
│   ├── main.py
│   ├── api/
│   │   ├── batches.py
│   │   ├── tasks.py
│   │   ├── uploads.py
│   │   └── system.py
│   ├── core/
│   │   ├── config.py
│   │   └── database.py
│   ├── models/
│   │   ├── batch.py
│   │   └── task.py
│   ├── schemas/
│   └── services/
│       ├── batch_parser.py
│       ├── comfyui_client.py
│       ├── workflow_adapter.py
│       ├── task_tracker.py
│       └── output_service.py
```

### 8.1 batch_parser

负责：

- 校验 `POEM_VIDEO_BATCH_V1`
- 解析 [GLOBAL]
- 解析 [SCENE:*]
- 保留多行 Prompt
- 保留多行 Negative Prompt
- 校验场景编号
- 输出结构化 JSON

### 8.2 workflow_adapter

负责：

1. 读取 API Workflow 模板。
2. 深拷贝模板。
3. 根据映射配置替换节点输入。
4. 生成唯一输出名前缀。
5. 返回可直接 POST 到 ComfyUI `/prompt` 的 JSON。

节点 ID 不允许硬编码散落在业务代码中，应集中配置，例如：

```yaml
workflow:
  image_node: "12"
  prompt_node: "35"
  negative_prompt_node: "36"
  speech_node: "41"
  video_node: "45"
  save_node: "50"
```

具体节点 ID 必须以服务器当前成功运行的 Workflow API JSON 为准。

### 8.3 comfyui_client

封装：

- `POST /prompt`
- `GET /queue`
- `GET /history/{prompt_id}`
- ComfyUI WebSocket
- 失败重连
- 超时处理

### 8.4 task_tracker

维护应用侧任务状态，并将 ComfyUI 的 prompt_id 映射回诗词场景。

## 13. 配置项

`.env` 至少包含：

```env
COMFYUI_BASE_URL=http://host.docker.internal:8188
COMFYUI_WS_URL=ws://host.docker.internal:8188/ws
```

## 15. 错误处理

必须覆盖：

- 上传文件失败
- 批量文本解析失败
- 场景数与图片数不匹配
- Workflow 模板不存在
- Workflow 节点映射失效
- ComfyUI 不可达
- ComfyUI 返回错误
- WebSocket 断开
- 视频生成失败
- 输出文件未找到

失败必须落库并在前端显示具体原因，不允许只显示“生成失败”。

## 16. V1.0 验收标准

以一首 4 句绝句为测试样例，具备 1 张封面 + 4 张诗句场景图。

完整验收流程：

1. 一次上传 5 张图片。
2. 一次粘贴完整 `POEM_VIDEO_BATCH_V1` 文本。
3. 点击“解析任务”后正确得到 5 个场景。
4. 每个场景正确绑定图片、Prompt 和 speech。
5. 点击一次“全部加入生成队列”。
6. 后端生成 5 份基于同一 Workflow 模板的任务。
7. 5 个任务均成功进入 ComfyUI Queue。
8. 页面可以实时看到 queued / running / completed 状态变化。
9. 每个场景生成独立 MP4。
10. 5 个视频均可在页面单独预览或下载。
11. 单个任务失败后可以单独重试。
12. 不需要用户再次复制、粘贴 Prompt 或手工在 ComfyUI 重复操作。

达到以上 12 项，视为 PoemVideo Studio V1.0 可用。

## 18. 当前开发前置条件

开始接入 ComfyUI 前，必须从当前服务器正在成功使用的 MiniMax H3 工作流中导出 **API Format Workflow JSON**。

必须实际确认以下节点：

- 首帧 image 节点
- 正向 Prompt 节点
- Negative Prompt 节点
- speech / audio 文本节点
- width / height
- fps / num_frames
- 输出 SaveVideo 节点

以真实 Workflow 为唯一依据，不根据节点名称或历史截图猜测节点 ID。

---

**V1.0 总结：PoemVideo Studio 不重做 MiniMax H3，而是把现有成功的 ComfyUI 单视频工作流包装成“整首诗一次输入、一次提交、自动排队、逐段生成”的批量生产工具。**
