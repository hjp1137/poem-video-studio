## 后端接口

- POST /api/h3/keyframes/generate
- 表单字段：first_frame、last_frame、prompt、width、height、duration、seed、turbo
- 返回 video/mp4；测试文件保存在 Studio 数据卷的 outputs/keyframe-tests
- 校验图片类型、30MB 大小上限、分辨率 32 对齐、24fps 和 4~15 秒时长
- 错误明确报告 H3 实际 HTTP 状态和响应，不偷偷回退成单首帧

H3 原生同步端点： http://127.0.0.1:8000/v1/videos/sync 。接口字段重点为：

    extra_params={"task":"fl2va","duration":5.0,"frame_indices":[0,-1],"audio_flow_shift":3.0}
    input_references: 首帧图片（第一个同名 multipart 字段）
    input_references: 尾帧图片（第二个同名 multipart 字段）

官方参考： https://github.com/vllm-project/vllm-omni/blob/main/recipes/MiniMaxAI/MiniMax-H3.md

## Turbo 模式

- 原版：50 个 sigma 点、flow_shift=12，不激活 LoRA。
- Turbo 8-step：9 个 sigma 点、flow_shift=6、audio_flow_shift=3。额外传 lora 字段，路径从 H3_TURBO_LORA_PATH 读取。
- 服务端需要已以 PEFT 方式加载对应 FL2VA Turbo LoRA。不要把 Ref2VA LoRA 误用在此模式。
- 同一轮 A/B 验证应固定图片、prompt、seed、分辨率及视频时长。

## 与现有 Studio 的关系

新 Vue 路由为 /keyframes，点击【首尾帧测试】即可上传两张图、生成并下载 MP4。为了降低回归风险，暂时不改变原有 [SCENE] 解析器、Workflow Adapter 或 Batch 表，未来将测试通过的双帧处理纳入正式批量队列。

后端新增两个配置，设置在 Studio 的 .env 中：

    H3_API_BASE_URL=http://host.docker.internal:8000
    H3_TURBO_LORA_PATH=/data/AI_Models/MiniMax-H3/Turbo/minimax_h3_fl2v_turbo_8step_v1.0_768p_bf16.safetensors

注意：host.docker.internal 是 Studio API Docker 容器访问宿主 H3 的地址；不等于浏览器地址。请保证容器能连宿主 8000，并且不要让 Studio API 的宿主机端口和 H3 8000 冲突。

## 上线测试

先备份 Studio .env，确认当前 Git 工作目录没有未提交的生产改动。开发分支合并/部署到 Studio 服务器后：

1. 检查 H3：curl http://127.0.0.1:8000/health
2. 执行 Studio 后端单测：cd backend && python -m pytest tests/test_h3_keyframes.py -q
3. 执行前端检查：cd frontend && pnpm run typecheck
4. 在 Studio 网站打开 /keyframes，先使用两张同画幅图片，选择原版50步生成 5 秒。
5. 确认输出首帧、尾帧与输入相符，然后测试 Turbo 8-step，比较画面稳定性和耗时。
6. 执行原有单首帧诗词批量生成功能回归测试。
7. 如果服务不支持 input_references / frame_indices，记录错误及日志；隔离升级 H3，不要覆盖当前生产环境。

## 访问安全

Studio 现阶段为内网服务，当前首尾帧测试端点与现有 API 保持同样权限边界，尚未提供独立账户认证。多人长期使用前应增加身份认证、配额/队列、上传清理与审计。
