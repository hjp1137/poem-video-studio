# MiniMax H3 首尾帧生成接入（试验分支）
日期：2026-10-12

## 目标
在 PoemVideo Studio 每个诗句场景增加可选的「尾帧」图片，不改变现有首帧批量工作流。通过已有 ComfyUI（8188）→ vLLM-Omni（8000）→ MiniMax H3 FL2VA 生成视频。首尾帧严格区别于 Ref2VA 多参考图。

## 现状与边界
- 当前 Studio 通过 workflow_adapter.py 的 workflow-map.yaml 注入一张 image，任务模型仅有 image_path。
- 本分支已在适配器支持 last_image 映射及 build(last_image_name=...)；该适配器接口修改还**不能**独立实现上传、持久化和 UI。
- 已确认用户服务器更新节点源码含 first_frame 和 last_frame。后端版本为 3d71a2b3；其与新节点的首尾帧协议尚需真机端到端验证。
- 不修改现有 vllm-omni 和 FL2VA 模型，不替换现有默认工作流。

## 完整实现契约（待开发）
1. 批次创建 CreateBatchRequest 增加可选 last_image_bindings（scene_key → 已上传文件 id）。
2. 每个 VideoTask 存储 last_image_path，提供数据库无损迁移；旧批次值为空。
3. 每个场景允许「只有首帧」或「首帧＋尾帧」；缺首帧仍按当前验证失败；尾帧缺省不影响旧任务。
4. 前端场景卡片增加「上传/选择尾帧」「清除尾帧」与两张缩略图，清晰标识首帧、尾帧。
5. 提交队列时上传两张图片至 ComfyUI 的 input，渲染 workflow-map 所指的两个 Load Image 节点；Generate Video.first_frame/last_frame 连线必须在 API Workflow 模板中预先存在。
6. workflow-map 为首帧映射 image、尾帧映射 last_image；未启用尾帧时使用专门的“首帧模式”模板，避免无输入的尾帧节点报错。支持两模板自动路由或从模板中删除尾帧关联；不得传空文件名。
7. 设置前检查模板 object_info 和实际节点定义。若新前端与旧后端协议不兼容，报可诊断错误，保留旧方案。
8. H3 Turbo 8-step 不作为首尾帧模式的默认：先在原生采样条件下验证首尾帧，再测 8-step 的兼容性、画质、吞吐。

## 测试
- 单测：旧单首帧任务、双帧任务、缺尾帧文件、模板无 last_image、映射错误、重复 scene_key、非法尾帧 id。
- 集成：上传首尾两张图→建批次→工作流注入→/prompt→/history→/view 成功下载；另一场景仅首帧仍能成功。
- 真机测试：768×1024，24fps，5秒（H3 框架允许的时长/帧数以实际后端返回为准），一组首尾不同构图的诗词场景；首尾截图检查、耗时、显存、音轨。
- 并行稳定性：确保 H3 四卡、DLO、320/280W 上限设置不被 PoemVideo Studio 改动。

## 验收标准
每个场景能分别上传首帧、尾帧，实时查看缩略图，批量排队与下载；旧单首帧批次完全可用；失败可重试、日志能定位；测试结果为成功之前不得合入 main。
